# 深圳中继方案（定稿）

> 状态：已实现 2026-10-17 → ../test/2026-10-17-中继单测.md

## 目标

跨盘转存（夸克 → 115）不再依赖德国机器上传：115 秒传确认未命中的文件，交给深圳 ECS 下载并上传。
默认链路不变，中继只在「确认未命中」时介入。

## 数据流

```
插件（德国 MP）
  └─ 115 秒传探测（upload_file_init，命中即结束）
       └─ 未命中 且 文件 ≤ 上限
            └─ POST /jobs → 深圳中继
                  ├─ 夸克 fid → 直链（PC 客户端 UA）
                  ├─ Gopeed 多连接下载到本地临时盘
                  ├─ 115 上传：p115client init + p115oss 分片并发
                  │    └─ OSS 端点 oss-cn-shenzhen → -internal
                  └─ 返回 success + 文件身份
            └─ 插件 find_file 确认 → 继续重命名/整理
```

## 关键决定

1. 插件只发**文件身份**（源盘 fid、大小、SHA1、目标目录/文件名），不发直链：中继用本地 cookie 自己取链，避免直链跨 IP 失效。
2. 判定点沿用现有「先探测后下载」：只有 115 明确返回未命中才转发，不做二次猜测。
3. 中继串行处理任务（35 GB 盘同时只能容一个文件），下载/上传各占一条腿。
4. 上传端点固定改写为内网域名，保留 bucket 前缀（`fhnfile.oss-cn-shenzhen-internal.aliyuncs.com`）。
5. 失败策略默认回落本机；稳定后可关，改为直接报错。
6. 鉴权只用一个共享令牌（`X-Token`），中继不暴露 Gopeed。

## 验收

- 中继单测 8 例：配置校验、内网 URL 改写、成功链路、SHA1 不符、超限拒绝、HTTP 鉴权。
- 插件单测 4 例：中继成功/失败/提交异常/禁止回落。
- 真机：一部跨盘剧集，日志出现 `115 秒传未命中，已交给深圳中继`，任务成功且文件出现在 115 目标目录。
