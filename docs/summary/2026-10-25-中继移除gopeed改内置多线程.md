# cs-relay 0.7.0：移除 Gopeed，改内置多线程下载

日期：2026-10-25

## 结论

深圳中继不再部署 `cs-gopeed` 容器，下载腿只有 `relay/downloader.py` 一套内置多线程
Range 分片。`docker-compose.yml` 只剩 `cs-relay` 一个服务，`.env` 里的 `GOPEED_*`、
`RELAY_DOWNLOAD_ENGINE`、`QUARK_EXT_AUTO` 全部失效（不再读取）。

## 为什么

1. **Gopeed 要额外一整套东西**：独立容器 + `liwei2633/gopeed` 镜像 + 夸克扩展
   （`igwkang/gopeed-extension-quark`，devMode 安装）+ 扩展里单独写一份 cookie；
   扩展那份 cookie 过期后只报 `status=error`，看不出原因。
2. **请求头不可控**：Gopeed 侧丢 cookie/UA 时夸克直链 403，中继拿不到失败细节。
3. **内置下载器早就写好并默认启用**（`RELAY_DOWNLOAD_ENGINE=builtin` 是 0.5.x 的默认值），
   Gopeed 只是遗留的第二条腿，维护成本大于收益。
4. **速度上 Gopeed 没有优势**：夸克下行实测 4 并发 7.9 MB/s、16/32 并发 7.3/6.7 MB/s，
   真正的瓶颈是 VPS 上行约 2.5 MB/s，与客户端无关。

## 改了什么

| 文件 | 改动 |
| --- | --- |
| `relay/gopeed.py` | 删除 |
| `relay/quarkext.py` | 删除（只为 Gopeed 安装夸克扩展） |
| `relay/config.py` | 删 `gopeed_url/token/connections`、`download_engine`、`quark_ext_auto`；新增 `download_connections`（`RELAY_DOWNLOAD_CONNECTIONS`，默认 32，1–128）、`download_chunk_bytes`（`RELAY_DOWNLOAD_CHUNK_MB`，默认 8） |
| `relay/jobs.py` | 只保留内置下载腿；连接数取任务自带 `connections` 或配置默认值；分片大小走 `download_chunk_bytes` |
| `relay/downloader.py` | 并发上限 32 → 128 |
| `relay/server.py` | 删 `/debug/gopeed/{test,install-quark,proxy}`；新增 `POST /debug/download`（真实跑一次下载，按秒截断，回报实测 MB/s）；`selfcheck`/`status` 改报下载腿参数；VERSION → 0.7.0 |
| `relay/__main__.py` | 删扩展自举逻辑，启动日志打下载腿配置 |
| `docker-compose.yml` | 删 `gopeed` 服务与 `depends_on`，镜像 tag 0.7.0 |
| `.env.example` | 只留新变量 |
| `README.md` | 重写下载腿与部署/升级/排障章节 |
| `tests/` | 删 `test_quarkext.py`；`FakeGopeed` 换成 patch `relay.jobs.downloader.download`；新增配置钳制、`/debug/download` 参数校验用例 |

## 部署（深圳 /opt/csrelay）

```bash
cd /opt/csrelay
curl -fsSL -o /tmp/cs.tar.gz https://ghfast.top/https://github.com/xymhh/cs-relay/archive/refs/heads/main.tar.gz \
  && tar -xzf /tmp/cs.tar.gz --strip-components=1 \
  && docker compose rm -sf gopeed \
  && docker compose up -d --build \
  && curl -s -H "X-Token: $RELAY_TOKEN" http://127.0.0.1:8787/debug/status
```

跑通后确认：

```bash
# 实测下载速度（用任意一个夸克 file_id，8 秒截断）
curl -s -H "X-Token: $RELAY_TOKEN" -H 'Content-Type: application/json' \
  -d '{"file_id":"<fid>","seconds":8}' http://127.0.0.1:8787/debug/download
```

## 遗留

- 本地 Python 3.11 下 `p115client 0.0.9.7.2` 有 PEP 701 语法错误，`relay/p115.py`
  的 import 兜底从 `except ImportError` 放宽到 `except Exception`，否则测试无法收集；
  生产镜像 3.12 不受影响。
- 旧 Gopeed 的 `./downloads`、`./storage` 目录可直接删除（中继不读）。

## 实测（2026-10-25，深圳 ECS → 夸克，文件 Stranger Things S05E04 12.4 GB）

`POST /debug/download` 按秒截断测速（同一 file_id，逐次调用）：

| 连接数 | 时长 | 实测 |
| --- | --- | --- |
| 4 | 8 s | 0.64 MB/s |
| 8 | 10 s | 0.63 MB/s |
| 16 | 8 s | 2.68 MB/s |
| 32 | 10 s | **8.60 MB/s** |
| 32 | 20 s | 1.47 / 4.72 MB/s（两次差异大） |
| 64 | 8 s | 5.66 MB/s |
| 64 | 20 s | 3.00 MB/s |
| 128 | 8 s | 5.38 MB/s |

结论：连接数从 4 提到 32 有量级差异（0.6 → 8.6 MB/s），32 以上不再增长；
单次结果波动大（1.5–8.6 MB/s），说明上限取决于夸克 CDN 对这台机出口 IP 的实时带宽，
不是中继自身的瓶颈。默认 32 连接保留。

另修：`/debug/selfcheck` 里 `credentials` 缺 `ok` 字段，导致整体 `ok=false`（0.7.1）。
